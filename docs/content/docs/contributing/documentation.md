Documentation changes follow the same evidence rules as code.

## Writing rules

- Describe current behavior in the present tense.
- Label proposals and future work explicitly.
- Link conclusions to an experiment, test, artifact, or external source.
- Record limitations and unknowns next to the conclusion they qualify.
- Prefer one canonical explanation over duplicated summaries.

## Experiment pages

An experiment page must state:

1. The question being tested
2. The single controlled variable
3. The repeatable procedure
4. The observations collected
5. Every normalization applied
6. The result and evidence state
7. Known limitations

Run the local documentation server and check changed pages before opening a
pull request. Documentation merged into `main` is published automatically by
the GitHub Pages workflow.
